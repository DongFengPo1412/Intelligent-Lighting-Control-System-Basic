## オフライン音声設定とイベント

ウェイクワード、命令、ID、応答音声を設定し、リソース生成後にアプリコードとビルドして書き込みます。生成だけでは端末への配置は完了しません。オフラインとは端末実行時の動作で、開発ツールや生成サービスはネット接続を必要とする場合があります。

`ASR_CODE`はSDKから渡される`snid`で動作を振り分けます。イベント処理入口であり、名前だけでハードウェア割込み処理とは判断できません。固定語句の照合は自由対話やLLM理解ではありません。音声リソースはプラットフォームを利用し、独自音響ネットワークの学習処理は同梱していません。

ASRPROプログラミングモード手引き21ページには、既定の起動状態終了時間が15秒とあります。保存アプリに共通の明示的設定はなく、SDK版に依存するプラットフォーム既定値として説明し、独自開発のタイマー状態機械とはしません。

口形は固定フレームと遅延で応答に合わせます。音素抽出、音声進行取得、位相同期のフィードバックはありません。長いアニメやランダム棒ループを即座に音声で中断できるかはSDKと実機の確認が必要で、全モードの任意終了は本コードから確定できません。

## 点描データと座標アルゴリズム

### 二値パターンとRGBデータ

各行を`uint16_t`で表し、1ビットが1灯に対応します。1の画素を指定色で描画します。行マスクM_yに対し、コードは`pattern[y] & (1 << (15-x))`を確認します。

```math
b(x,y)=\left(M_y\gg(15-x)\right)\mathbin{\&}1,\qquad 0\le x,y<16
```

単色とは1フレーム内の点灯画素が同じRGB色という意味で、白黒限定ではありません。複数配列で泣き顔や口形を作ります。4色表情表示は4種類を3巡し、各フレームで`delay(1000)`を呼びます。

静止キャラクターはred・green・blueの16×16配列を使います。格納サイズは次式です。

```math
S_{\mathrm{binary}}=16\times2=32\ \mathrm{bytes},\qquad S_{\mathrm{RGB}}=3\times16\times16=768\ \mathrm{bytes}
```

![RGBキャラクター素材](images/demo_pixel_desktop_pet.png)

これは静止ピクセル素材で、実機写真や動くデスクトップペットの動作証拠ではありません。

### 8×8パネル4枚のマッピング

`贪吃蛇.hd:getPixelIndex`は0始まりの座標を使います。qは左上・右上・左下・右下のパネル番号で、内部を行順に数えます。この式はコードの前提を示し、全実物パネルの内部配線を検証したものではありません。

```math
q=2\left\lfloor\frac{y}{8}\right\rfloor+\left\lfloor\frac{x}{8}\right\rfloor,\qquad
i=64q+8(y\bmod8)+(x\bmod8)
```

(8,0)は分割式で64ですが、初期`displayPattern`の`y*16+x`では8です。全ファイルが同じ写像とはいえません。RGB処理は4区画へ出力しますが、16×16配列を1–16で参照しており、修正前に0始まりの式と等価とは認定できません。

### ドライバと理論伝送時間

アプリはSDKの初期化、色設定、`pixel_show()`を呼びます。低層波形コードやオシロスコープ記録は含みません。800 kbit/s、1灯24 bitと仮定した256灯の理想データ時間は次式です。

```math
T_{\mathrm{wire}}=\frac{256\times24}{800000}=7.68\ \mathrm{ms},\qquad
T_{\mathrm{frame}}\ge T_{\mathrm{wire}}+T_{\mathrm{reset}}
```

リセット、計算、ライブラリ、タスクの時間が加わります。理論帯域を実測更新率、アニメのフレームレート、独自のナノ秒波形制御成果とは扱いません。パルスとリセット条件は実物のWS2812B型式・資料版に合わせます。

## 音楽断片とランダム照明

参加者は固定応答音声を楽曲断片へ差し替えて再生したと説明しています。該当音声は未同梱です。`功能三.hd`は`rand()%17`で高さ、`rand()%256`でRGBを生成し、表示ループで200 msのタスク遅延を入れます。

音声サンプリング、FFT、音量包絡、拍の抽出はありません。「音楽再生に伴うランダム照明」または「擬似音楽可視化」と表現します。固定断片はストリーミング再生ではありません。停止命令の分岐はありますが、長いイベントループ中に新イベントを受けられるかは未確認です。

## スネークとシリアルタスク

| 処理 | 実装と目的 |
| :--- | :--- |
| 初期化 | `resetGame()`で3節、右方向移動、食物、得点リセットを設定。 |
| 受信 | `UART_RX`が115200 bpsで文字を読み、外側ループで2 ms待機。 |
| 更新 | `app`が開始状態なら`moveSnake()`を呼び、300 ms待機。厳密な300 ms周期ではありません。 |
| 方向制限 | 現在のdx/dyで直接逆向きを拒否。同一ステップ内の連続転向は要確認。 |
| 境界折返し | 0–15を越えると反対側へ移動し、下式と等価。 |
| 食物 | 乱数座標を作り、`isOnSnake`で胴体との重複を除外。 |
| 移動と成長 | 胴が頭を追い、食べた際は旧尾の位置を追加して加点。 |
| 終了 | 自身衝突で停止し、300 ms点灯・消灯を3回繰り返してシリアル得点を出力。 |

```math
x'=(x+\Delta x+16)\bmod16,\qquad y'=(y+\Delta y+16)\bmod16
```

両タスクの優先度は4、スタック深度引数は256で、単位はSDK依存です。方向・状態は共有変数で渡し、アプリ側の環状命令キュー、ミューテックス、明示的な原子操作はありません。受信を分離しても表示応答にはゲーム更新・駆動時間が加わり、ループ遅延から通信実測値は導けません。

`E`は停止中のみ開始・再開始し、実行中の即時リセットはしません。保存版`showScore()`は`Serial.print/println`で、数字字模の描画はありません。音声開始、LED得点、統一モード切替はデモ対応コードの補完が必要です。
