## 离线语音配置与事件绑定

开发流程是配置唤醒词、命令词、识别 ID 与回复音频，生成资源，再与应用代码编译下载。生成资源本身不等于已经部署。离线指设备运行时不依赖网络；开发工具或资源生成服务可能需要联网。

`ASR_CODE` 根据 SDK 提供的 `snid` 分发动作。它是识别事件处理入口，不能仅凭函数名认定为硬件中断服务程序。固定词条匹配也不等于自由对话或大模型语义理解。语音识别与生成资源来自平台，仓库未提供团队自行训练声学网络的流程。

ASRPRO 编程模式手册第 21 页说明默认唤醒退出时间为 15 秒。归档应用未显式设置统一超时，因此只能作为平台默认机制说明，具体仍需匹配 SDK 版本；不能将其写成团队开发的定时状态机。

口型以预设帧和延时配合回复播放，没有音素提取、音频进度读取或锁相反馈。较长的动画及随机灯柱循环能否被唤醒词即时打断，需要实机和 SDK 调度验证；本归档不能证明任意模式均可随时退出。

## 点阵数据与坐标算法

### 二值图案与 RGB 数据

每行用一个 `uint16_t` 存储 16 个像素；位为 1 时绘制指定颜色。令 M_y 为第 y 行的位掩码，代码用 `pattern[y] & (1 << (15-x))` 判断像素：

```math
b(x,y)=\left(M_y\gg(15-x)\right)\mathbin{\&}1,\qquad 0\le x,y<16
```

单色在这里指同一帧中亮起像素使用同一 RGB 色，不是只能显示黑白。多帧数组形成哭脸、口型等预设动画；四色表情轮播遍历四种表情、重复三次，每帧调用 `delay(1000)`。

静态角色使用 red、green、blue 三个 16×16 数组，分开存储三个颜色通道。数据占用为：

```math
S_{\mathrm{binary}}=16\times2=32\ \mathrm{bytes},\qquad S_{\mathrm{RGB}}=3\times16\times16=768\ \mathrm{bytes}
```

![RGB 角色图案素材](images/demo_pixel_desktop_pet.png)

这是静态像素图案素材，不是实机照片或动态桌宠运行证据。

### 四块 8×8 面板的分块映射

`贪吃蛇.hd:getPixelIndex` 使用零起点坐标。q 为面板编号，四块依次为左上、右上、左下、右下；各块内按行计算。该编号描述代码假设，不代表已经核验所有实物灯板内部走线。

```math
q=2\left\lfloor\frac{y}{8}\right\rfloor+\left\lfloor\frac{x}{8}\right\rfloor,\qquad
i=64q+8(y\bmod8)+(x\bmod8)
```

例如 (8,0) 在分块映射中为64，早期线性 `displayPattern` 中为8。RGB修订版与游戏使用相同的零起点分块式，但单色表达仍保留线性映射；按所选程序核对接线。

### 驱动与理论传输时间

应用调用 SDK 的初始化、颜色设置与 `pixel_show()`，仓库没有底层波形驱动实现或示波器记录。若按 800 kbit/s、每灯 24 bit 估算，256 灯仅数据发送的理想时间为：

```math
T_{\mathrm{wire}}=\frac{256\times24}{800000}=7.68\ \mathrm{ms},\qquad
T_{\mathrm{frame}}\ge T_{\mathrm{wire}}+T_{\mathrm{reset}}
```

复位间隔、处理时间、库实现和任务调度还会增加开销。因此不能将理论传输上限当作实测刷新率、动画帧率或本项目的纳秒时序控制成果。WS2812B 的具体脉宽与复位要求需匹配灯珠型号及资料版本。

## 音乐片段与随机灯柱

参与者将预设回复音频替换为固定歌曲片段，以命令触发播放；相关音频资源未随仓库提供。`功能三.hd` 使用 `rand()%17` 生成柱高、`rand()%256` 生成 RGB 颜色，并以 200 ms 的任务延时循环显示。

这里没有音乐采样、FFT、响度包络或节拍提取。准确名称是“音乐播放配合随机灯效”或“模拟音乐律动”。播放指定预置片段也不等于支持流媒体点歌。停止命令虽有分支，但同一事件函数中的长循环能否接收新事件仍需验证。

## 贪吃蛇与串口任务

| 机制 | 实现与用途 |
| :--- | :--- |
| 游戏初始化 | `resetGame()` 建立三节蛇、默认向右移动、生成食物并清零得分。 |
| 接收任务 | `UART_RX` 以 115200 bps 读取可用字符，每次外层循环延时 2 ms。 |
| 更新任务 | `app` 在游戏开始时调用 `moveSnake()`，随后延时 300 ms；不是严格固定的 300 ms 周期。 |
| 方向限制 | 游戏步开始时读取最新方向，对照上一已提交方向拒绝直接反向。 |
| 边界穿越 | 超出 0–15 后折返到另一侧，等价于下式的环绕边界。 |
| 食物生成 | 枚举未占用位置并随机选一个；无空格时返回结束。 |
| 移动与增长 | 蛇身依次跟随，吃食物时追加旧尾部位置并加分。 |
| 结束反馈 | 自碰撞后停止游戏，红灯亮／灭各 300 ms、重复三次，再输出串口分数。 |

```math
x'=(x+\Delta x+16)\bmod16,\qquad y'=(y+\Delta y+16)\bmod16
```

两个任务优先级均为4、栈深度参数256，具体单位由SDK定义。串口任务仅用原子单槽请求向游戏任务传值，不再直接写dx/dy或重置蛇身；多次方向输入可能被最新值覆盖。300 ms更新延时与2 ms接收轮询不是实测响应时延。

`E` 只在游戏停止时开始或重启；游戏中发送 `E` 不会立即重置。归档版 `showScore()` 是 `Serial.print/println`，没有数字字模绘制。语音启动、LED 得分显示及统一模式切换需找回对应演示代码后补充。
